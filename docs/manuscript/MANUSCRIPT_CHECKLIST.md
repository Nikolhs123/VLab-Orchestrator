# SoftwareX manuscript checklist

## Current draft

- Draft: `SOFTWAREX_MANUSCRIPT_DRAFT.md`
- Target: SoftwareX Original Software Publication template, version 6 (March 2026)
- Maximum body length: 4,000 words
- Maximum figures: 6
- Required sections: Motivation and significance; Software description; Illustrative examples; Impact; Conclusions

## Proposed figure budget

1. Layered framework and adapter architecture.
2. Setup window and backend readiness workflow.
3. Session, queue, authority, and telemetry sequence.
4. Rights-cleared two-user showcase.
5. Five-scenario benchmark protocol.
6. Descriptive cross-backend results with anomaly-validation annotations.

## Required before submission

- Confirm complete author list, order, affiliations, ORCIDs, and corresponding author.
- Obtain institutional confirmation of code ownership and select an OSI-approved licence.
- Make the final repository public and create a versioned release.
- Archive the release and add its DOI or permanent identifier.
- Replace all square-bracket placeholders.
- Add and verify the remaining primary references.
- Generate balanced independent repetitions if making inferential performance claims.
- Produce publication figures from the final frozen data.
- Transfer approved text into the official Word template and remove template instructions.
- Confirm repository contains the final `README.md` and licence file.

## Comparison policy

- Compare capabilities against related reusable Unity and collaborative-XR software to establish the research gap.
- Compare backend observations only under the declared protocol and hardware.
- Report raw data, uncertainty, effect sizes, and protocol validity when replicated data are available.
- Do not rank a backend as universally best.
- Keep targeted anomaly reruns separate from the balanced experiment.
